# مسیر کانکور — سایت آموزشگاه کانکور

یک سایت کامل با بک‌اند و دیتابیس واقعی برای آموزشگاه کانکور: ویدیوهای درسی، آزمون‌های آنلاین، داشبورد پیشرفت شاگرد، و ثبت‌نام/پرداخت.

## ساختار پروژه

```
konkur-academy/
├── backend/     # سرور Node.js + Express + SQLite
└── frontend/    # رابط کاربری React + Vite + Tailwind
```

## پیش‌نیازها

- Node.js نسخه ۱۸ یا بالاتر (از nodejs.org دانلود کنید)
- یک ویرایشگر کد مثل VS Code

نیازی به نصب MySQL/MongoDB یا هر دیتابیس جداگانه نیست — همه‌چیز در یک فایل `data.sqlite` ذخیره می‌شود.

## راه‌اندازی بک‌اند

```bash
cd backend
npm install
cp .env.example .env
npm run dev
```

سرور روی `http://localhost:4000` بالا می‌آید. در اولین اجرا:

- جدول‌های دیتابیس به‌طور خودکار ساخته می‌شوند
- ۳ رشته/صنف نمونه (طب، انجینیری، اقتصاد)، ۳ کورس، چند ویدیو و یک آزمون نمونه اضافه می‌شوند
- دو حساب پیش‌فرض ساخته می‌شوند:
  - **مدیر:** `admin@konkur.test` / `admin123`
  - **استاد نمونه:** `teacher@konkur.test` / `teacher123`
  - ⚠️ حتماً بعد از اولین ورود این رمزها را تغییر دهید.

مستندات کامل API (Swagger UI) روی `http://localhost:4000/api/docs` در دسترس است.

## اجرای تست‌های بک‌اند

```bash
cd backend
npm test
```

تست‌ها (Jest + Supertest) روی یک دیتابیس موقت در حافظه اجرا می‌شوند و به `data.sqlite` واقعی دست نمی‌زنند. مسیرهای حیاتی مثل ثبت‌نام/ورود، جریان پرداخت (checkout → تایید ادمین → webhook) و کنترل دسترسی نقش‌ها (شاگرد/استاد/ادمین) پوشش داده شده‌اند.

## راه‌اندازی فرانت‌اند

در یک ترمینال جدید:

```bash
cd frontend
npm install
npm run dev
```

سایت روی `http://localhost:5173` باز می‌شود و به‌طور خودکار به بک‌اند وصل می‌شود.

## امکانات فعلی

**برای شاگردان:**

- ثبت‌نام و ورود (JWT) + انتخاب رشته/صنف
- لیست کورس‌ها با قیمت (یا رایگان)، ثبت‌نام/خرید کورس
- پخش ویدیوهای درسی + ذخیره‌ی خودکار پیشرفت تماشا
- آزمون آنلاین چهارگزینه‌ای + نمره‌دهی خودکار + امتیاز برای لیدربورد
- **لیدربورد** رقابتی بین شاگردان (کلی یا بر اساس رشته)
- **کلاس آنلاین زنده** با ویدیو-کنفرانس واقعی (Jitsi Meet رایگان، بدون کلید API)
- **انجمن پرسش‌وپاسخ** برای هر کورس (سوال از استاد، پاسخ استاد/مدیر مشخص می‌شود)
- **اعلان‌های داخل سایت** (زنگ 🔔 در نوار بالا): درس جدید، آزمون جدید، کلاس زنده، پاسخ انجمن، تایید پرداخت
- داشبورد شاگرد: پیشرفت هر کورس، نتایج آزمون‌ها، رتبه و امتیاز، «مسیر کانکور»

**برای استادان (نقش جدا از ادمین):**

- پنل استاد اختصاصی (`/teacher`): فقط کورس‌های خودشان
- ساخت کورس، آپلود ویدیو، ساخت آزمون برای کورس‌های خودشان
- دیدن لیست شاگردان ثبت‌نام‌شده و وضعیت پرداخت هر شاگرد
- برنامه‌ریزی و برگزاری کلاس آنلاین زنده
- پاسخ‌دهی در انجمن پرسش‌وپاسخ

**برای مدیر (ادمین کل):**

- مدیریت رشته‌ها/صنف‌ها
- ساخت حساب استادان جدید و تخصیص کورس به آن‌ها
- تمام امکانات استاد برای همه‌ی کورس‌ها
- **صفحه‌ی آمار پیشرفته** (`/admin/stats`): مجموع شاگردان/استادان/کورس‌ها/درآمد، نمودار شاگردان به تفکیک رشته، درآمد به تفکیک کورس، میانگین نمرات آزمون به تفکیک کورس

## نکته درباره‌ی اعلان‌ها و کلاس زنده

- **اعلان‌ها** فعلاً فقط داخل سایت (زنگ 🔔) هستند. برای ارسال واقعی ایمیل/پیامک، باید یک سرویس مثل نودمیلر (SMTP) یا یک درگاه پیامک را در پروژه اضافه کنید و در نقاطی که `db.notify(...)` صدا زده می‌شود، ارسال ایمیل/پیامک را هم اضافه کنید.
- **کلاس آنلاین زنده** از سرور عمومی و رایگان [Jitsi Meet](https://meet.jit.si) استفاده می‌کند — نیازی به ثبت‌نام یا کلید API نیست. برای حریم خصوصی بیشتر در مقیاس بزرگ، می‌توانید یک سرور Jitsi اختصاصی راه‌اندازی کنید یا از سرویس‌هایی مثل Daily.co یا Zoom API استفاده کنید.

## نکات مهم برای رفتن به نسخه‌ی واقعی (Production)

۱. **آپلود ویدیو (Bunny Stream):** پروژه اکنون از [Bunny Stream](https://bunny.net/stream/) پشتیبانی می‌کند. با تنظیم `BUNNY_STREAM_LIBRARY_ID` و `BUNNY_STREAM_API_KEY` در `.env`، آپلود ویدیوهای جدید به‌جای دیسک سرور مستقیم به Bunny فرستاده می‌شود و پخش از طریق CDN (سریع‌تر در سراسر افغانستان) و پخش‌کننده‌ی تعبیه‌شده‌ی Bunny انجام می‌شود. پیشرفت تماشا از طریق [Playback Control API](https://bunny.net/docs/playback-control-api) بانی همچنان به‌طور خودکار ذخیره می‌شود. اگر این دو متغیر خالی بمانند، رفتار قبلی (ذخیره روی دیسک محلی زیر `backend/uploads`) بدون تغییر ادامه پیدا می‌کند — ویدیوهای آپلودشده‌ی قبلی هم دست‌نخورده باقی می‌مانند.

   برای راه‌اندازی: در پنل Bunny یک Video Library بسازید، از بخش «API» شناسه‌ی کتابخانه (`Library ID`) و کلید (`API Key`) را کپی کنید و در `.env` بگذارید.

۲. **درگاه پرداخت:** پروژه اکنون دو مسیر پرداخت واقعی دارد:

   - **حواله بانکی + تایید دستی ادمین** (روش `bank`/`manual`): شاگرد وجه را جدا حواله می‌کند، ادمین از پنل (`/admin`) پرداخت را تایید یا رد می‌کند. همیشه فعال است، نیازی به کلید API ندارد.
   - **پرداخت با کارت از طریق Stripe Checkout** (روش `card`): با تنظیم `STRIPE_SECRET_KEY` و `STRIPE_WEBHOOK_SECRET` در `.env` فعال می‌شود. تا وقتی این مقادیر خالی باشند، دکمه‌ی «پرداخت با کارت» با خطای ۵۰۳ رد می‌شود و فقط حواله بانکی در دسترس است.

   **نکته‌ی مهم درباره‌ی واحد پول:** افغانستان کشور پشتیبانی‌شده‌ی Stripe نیست و AFN (افغانی) یکی از ارزهای پشتیبانی‌شده‌ی Stripe نیست. به همین دلیل قیمت کارتی به‌صورت خودکار از قیمت افغانی (`course.price`) محاسبه نمی‌شود — تبدیل با یک نرخ ارز ثابت/فرضی می‌تواند مبلغ نادرستی از کاربر بگیرد. به‌جای آن، هر کورس یک فیلد جدا به نام `price_usd` دارد که مدیر باید آن را صریحاً در فرم «ساخت کورس» وارد کند؛ اگر خالی بماند، پرداخت کارتی برای آن کورس غیرفعال می‌ماند.

   برای راه‌اندازی Stripe:
   1. کلید مخفی را از [dashboard.stripe.com/apikeys](https://dashboard.stripe.com/apikeys) بگیرید و در `STRIPE_SECRET_KEY` بگذارید.
   2. در Stripe Dashboard یک وبهوک برای آدرس `https://<دامنه‌ی-بک‌اند>/api/payments/stripe-webhook` بسازید و رویدادهای `checkout.session.completed`، `checkout.session.async_payment_failed` و `checkout.session.expired` را انتخاب کنید.
   3. سیکرت وبهوک را در `STRIPE_WEBHOOK_SECRET` بگذارید.
   4. مستند کامل هر دو endpoint (`/api/payments/checkout` و `/api/payments/stripe-webhook`) در `/api/docs` موجود است.

۳. **میزبانی (Hosting):** برای انتشار واقعی، بک‌اند را می‌توانید روی سرویس‌هایی مثل Railway، Render یا یک VPS اجرا کنید و فرانت‌اند را روی Vercel/Netlify یا همان سرور منتشر کنید.

   یک راه ساده‌تر برای VPS: پروژه یک `docker-compose.yml` آماده دارد که هر دو سرویس را با هم بالا می‌آورد:

   ```bash
   docker compose up --build -d
   ```

   بک‌اند روی پورت `4000` و فرانت‌اند (پشت nginx) روی پورت `8080` بالا می‌آید؛ نگین‌اکس درخواست‌های `/api` و `/uploads` را به‌طور خودکار به بک‌اند proxy می‌کند. دیتابیس (`data.sqlite`) و فایل‌های آپلودشده روی دو Docker volume جدا نگه‌داری می‌شوند تا با هر بازسازی ایمیج از بین نروند. قبل از اجرا مطمئن شوید `backend/.env` (از روی `.env.example`) ساخته‌اید. اگر فرانت‌اند و بک‌اند را جدا روی Vercel/Netlify + Railway/Render منتشر می‌کنید، به `docker-compose.yml` نیازی نیست.

۴. **امنیت:** مقدار `JWT_SECRET` در فایل `.env` را حتماً به یک رشته‌ی طولانی و تصادفی تغییر دهید و فایل `.env` را هرگز در گیت‌هاب پابلیک قرار ندهید.

## توسعه‌ی بیشتر (پیشنهادها)

- افزودن اعلان از طریق ایمیل/پیامک برای یادآوری آزمون‌ها
- گزارش پیشرفت مقایسه‌ای بین شاگردان یک صنف (لیدربورد)
- **نسخه‌ی موبایل:** یک اسکلت اولیه‌ی Expo در `frontend/mobile/` وجود دارد اما فعلاً خارج از محدوده‌ی MVP است — توسعه‌ی آن (صفحات ورود، لیست کورس، پخش ویدیو و غیره) به یک مرحله‌ی جداگانه موکول شده است.
